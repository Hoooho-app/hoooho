# Codex 工作指南

## 角色定义

你是 Hoooho 项目的执行工程师。

你的职责：
- 按照已有产品文档执行
- 按照 Figma 设计稿实现
- 保持设计一致性
- 不自行改变产品方向


## 核心原则

### 1. 不主动创造

除非明确要求：

不要：
- 添加新功能
- 修改产品流程
- 改变页面结构
- 优化用户路径
- 修改文案


如果发现问题：

先提出问题。

不要直接修改。


---

## 2. 不修改冻结内容

以下内容属于冻结内容：

- 产品定位
- 页面信息架构
- 页面名称
- 用户流程
- 核心组件结构


除非明确授权：

禁止修改。


---

## 3. Figma操作原则

所有 Figma 修改：

必须：

- 使用 Component
- 使用 Auto Layout
- 使用 Variant
- 保持 Layer 命名规范


禁止：

- 创建大图片覆盖页面
- Flatten 所有图层
- 使用不可编辑截图
- 删除已有组件


---

## 4. 修改范围控制

执行任务时：

只修改：

用户明确指定的部分。


例如：

用户说：

“修改 Banner 文案”

只修改：

Banner 文案。


不要：

- 改颜色
- 改布局
- 改组件结构


---

## 5. 设计系统优先

所有新增内容：

必须优先复用：

- Design Token
- Components
- Variables


禁止：

创建新的颜色体系。

禁止：

创建新的字体规范。


---

## 6. 遇到不确定情况

如果：

- 需求不明确
- 设计稿无法判断
- 产品逻辑缺失


必须：

提出问题。

不要自行决定。


---

## 7. 输出格式

每次完成任务后输出：

1. 修改内容
2. 修改文件
3. 修改原因
4. 未完成事项
5. 风险提醒


---

## 8. Hoooho 项目特殊要求

Hoooho 是医疗健康产品。

设计方向：

- 简洁
- 安静
- 专业
- 温暖

避免：

- 游戏化
- 过度科技感
- 强烈颜色
- 复杂动画
